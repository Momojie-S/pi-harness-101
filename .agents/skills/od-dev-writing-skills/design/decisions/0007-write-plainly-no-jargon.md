# 0007. 写清楚:通俗直白,别用缩写 / 自造黑话(可读性的语言落地)

- **Status**: accepted
- **Date**: 2026-08-06

## Context

`writing-craft.md` §0 立「可读性 = agent 能不能 follow」为核心认知,§1 给了一堆写法 craft(altitude / 指令式 / frontmatter / 结构 / form-to-failure / token / 调参归属),但**没有一条讲"语言本身要通俗直白、别用缩写 / 自造黑话"**。

后果:skill 正文反复出现读不懂的措辞,要读者(人 / 干净上下文的智能体)反复纠正。反复踩的几类(仅作证据,不入 skill 正文):

- **缩写 / 中英混杂黑话**:把「强制验证」压成「强验」、「裁紧写松」写成「crop tight / write loose」、「鼠标到位再点」写成「click 实锤」、「置信度 / 匹配失败」写成「conf / miss」。
- **堆修饰造名词**:「有界领域全集」「一类对象完整集合」(后改「要认全全部 boss」「该建的没建全」才通)。
- **反模式没标对错**:用「两个框别用反」这种模糊领起词,读者分不清下面是推荐还是错误做法。

非偶发(一条会话内 5+ 次,跨多条反馈),是 skill 没这条约束的系统性 gap。

## Decision

在 `writing-craft.md` 加 §1.9「写清楚:通俗直白,别用缩写 / 自造黑话」,作为可读性(§0)在语言层面的落地。判据(正文只给判据,具体黑话例子归本 ADR Context):

- 别用缩写 / 中英混杂黑话 → 用完整平实说法,首次术语带解释。
- 别堆修饰造名词 → 用动词 + 例子。
- 讲反模式时明确标「错 / 别犯」,别模糊领起。
- 判据:通读问"没参与讨论的人读得懂吗?"。

## Decision Drivers

- **可读性是核心认知(§0)但没语言层落地**:altitude / 结构 / token 都讲了,唯独"用词本身通俗"没讲 → 系统性产出难读措辞。
- **缩写 / 黑话对智能体更危险**:不只人读不懂,干净上下文的智能体可能误解执行(如把「强验」理解错)。
- **反模式不标对错 = 误导**:读者把错误做法当推荐执行,直接回归。

## Considered Options

### A. 加 §1.9「写清楚」判据(本决策)
- ✅ 把可读性落到语言层;判据级(不带具体黑话例子,合规 [0003](0003-methodology-not-examples.md))。
- ✅ "反模式标对错"直接防那类误导。

### B. 不加,判"§0 可读性已覆盖"
- 否决:§0 是认知(为什么要可读),没给"怎么写得可读"的语言判据。认知不等于 craft。

### C. 把具体黑话例子(强验 / crop tight / ...)写进 §1.9 正文
- 否决:违反 [0003](0003-methodology-not-examples.md)(skill 正文 + agent 读的辅助文件不写具体例子)。例子作证据归本 ADR Context(design/ 允许)。

## Consequences

- **正向**:skill 正文语言通俗;反模式标清对错;少踩缩写 / 黑话 / 堆名词。
- **代价**:写法 craft 多一条(§1.9);通读自检多一步。
- **推翻它会碎什么**:退回 B → 继续产出难读措辞;退回 C → 违反 0003(正文塞具体例子)。
