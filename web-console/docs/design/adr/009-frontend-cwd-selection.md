# ADR-009: 工作目录改为前端选择 + localStorage 记忆

## 状态

Proposed

## 背景

### 现状

工作目录由**启动时的环境变量** `ALLOWED_DIRS`（`;` 分隔，`server/index.ts` 启动时一次性读取）决定：

- 前端侧边栏「工作目录」区（`Sidebar.tsx`）按 `dirs`（= `ALLOWED_DIRS`）渲染按钮，点击 `onNewSession(cwd)` 建会话
- 后端 `open_session` / `open_history`（`server/ws.ts`）校验 `if (allowedDirs && !allowedDirs.includes(msg.cwd))` —— 精确匹配，不含子目录
- 未设白名单时：后端允许任意 cwd（`allowedDirs` 为 `null` 不拦截），但前端收到 `dirs: []` —— **侧边栏无任何入口**

### 两个问题

1. **加新项目要重启服务**。`ALLOWED_DIRS` 运行时不可变，要开发一个新项目必须改环境变量重启 web 服务。对一个**常驻服务**而言，重启 = 所有正在跑的会话中断（虽能从磁盘恢复，但流式 event 会丢，见 design.md「已知限制」）。
2. **白名单语义混淆**。`ALLOWED_DIRS` 同时承担两个角色：「安全边界」（限制可操作目录）与「便利入口」（侧边栏快捷按钮）。两者耦合导致「不设白名单」时**既不安全（允许任意 cwd）又不方便（无入口）**这一反直觉组合。

### 关键事实：白名单的安全意义有限

pi 的 bash 工具本质是**任意命令执行**。一个会话即使在 `D:/projA` 工作，也能 `cd ..` 或用绝对路径访问 `D:/projB`、甚至全盘。**白名单只能拦「前端把 cwd 设在哪」，拦不住 pi 实例通过 bash 跨目录访问**。

这条事实在 design.md「已知限制」里已有明确表述：

> Web 服务暴露的是对 pi 的**完全控制权**（文件读写、命令执行）……务必限制访问范围（Tailscale 内网 / 认证 / 工作目录白名单）

也就是说：**真正的安全边界在网络层**（Tailscale / 认证），工作目录白名单更偏向「便利 / 防误操作」。一旦接受这个判断，白名单的设计就可以更大胆地往「便利」倾斜，而不必在「安全」上过度纠结。

## 面临的选择

- **A. 前端选择 + localStorage 记忆（本决策）**：前端可直接输入/浏览选任意目录；localStorage 记「最近打开」；`ALLOWED_DIRS` 降级为可选根白名单（设了限浏览范围，不设完全放开靠网络层）。
- **B. 保留启动白名单，改配置文件运行时可写 + UI 增删**：白名单仍存在，但运行时可加目录，避免重启。
- **C. 启动白名单配「根目录」，前端在子树内浏览**：只配几个根，子目录自由建会话。
- **D. 维持现状**。

## 决策

选 **A**。具体三部分：

1. **前端**：侧边栏「工作目录」区改造为 —— 输入框（粘贴/输入绝对路径回车建会话）+ 「最近打开」列表（localStorage 记忆，点击秒建）。这是 MVP，零配置即可开发任意项目。后续可叠加目录浏览选择器。
2. **后端 `open_session` / `open_history`**：放宽 cwd 校验。`ALLOWED_DIRS` 语义从「精确目录白名单」降级为「可选根目录」——
   - 设了：要求 cwd 落在某个根的子树内（用 `path.relative` 检查，含子目录，比现状的精确匹配更实用）；
   - 不设：完全放开，靠网络层兜底。
   - 向后兼容：现有设了 `ALLOWED_DIRS` 的部署依然受限，只是范围从「精确目录」放宽到「根子树」。
3. **（浏览选择器增强）新增 `browse_dir` 消息**：不绑定会话，给定绝对路径返回其子目录；带可选根的越界检查。**不可复用现有 `list_dir`** —— 它绑定会话（先 `store.get(sessionId)` 再基于该会话 cwd 做 `path.relative` 越界检查），只能浏览「已打开会话 cwd 子树内」的目录；要用它选目录建会话是鸡生蛋。浏览选择器可后做，MVP 阶段输入框已够用。**【2025-08 已实现】**：`browse_dir` 消息 + `DirBrowser` 模态已落地——侧边栏输入框旁加 📁 浏览按钮，逐级进入 / 上级（越界拦截；Windows 盘符根的上级回到「盘符列表」，支持跨盘符）。起点 = 盘符列表（Windows 检测 C-Z）/ `allowedDirs` / 根目录；只列目录、过滤隐藏目录。实现见 `src/components/pickers/DirBrowser.tsx` 与 `server/ws.ts` 的 `browse_dir` case。

**选定目录后的行为（2025-08 演进）**：原方案是「选定 → 直接新建会话」；改为「选定 → 加载该目录的**历史会话列表**」（侧边栏内联，复用 `list_sessions` + `open_history`），滚动分页（前端按页切片 `visible` 游标），顶部提供「新建会话」。这样选目录后先看历史对话，可恢复任一历史或新建。实现见 `src/components/Sidebar.tsx` 的目录对话视图 + `src/state/sessionReducer.ts` 的 `dirSessions` 状态。

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A. 前端选择 + localStorage（本决策）** | 零配置、加项目不重启、贴近 IDE 心智模型、白名单语义清晰 | 放开 cwd 校验，强依赖网络层；目录浏览需新接口 |
| B. 白名单改配置文件运行时可写 | 保留白名单语义、可 UI 增删、避免重启 | 仍需逐个登记每个项目路径；不解决「粒度太细」 |
| C. 白名单配根目录 + 子树浏览 | 新项目零配置（放根下即可）、保留根级限制 | 仍需启动配根；不设根则前端无入口（老问题复发） |
| D. 维持现状 | 零改动 | 加项目要重启、语义混淆、不设白名单既不安全又不方便 |

> A 与 C 不互斥：A 的「可选根白名单」本质上吸收了 C 的「根级限制」思路，只是把根设为可选而非必填。

## 放弃了什么

- **cwd 维度的精确拦截**：前端可指定任意目录作为工作目录。但白名单本就拦不住 bash 跨目录访问（见「关键事实」），这道防线的实际安全价值有限，网络层才是真边界。
- **一点「防误操作」**：用户可能手滑选错目录。用可选根白名单 + 输入时的确认提示兜底，不强求拦截。

## 后果

### 正面

- **零配置、加项目不重启**：开发任意项目只需粘贴一次路径，后续从「最近打开」一键回到。体验接近 IDE。
- **白名单语义清晰**：`ALLOWED_DIRS` 纯做「限浏览范围 / 防误操作」，安全责任明确归网络层，不再混淆。
- **向后兼容**：现有设了 `ALLOWED_DIRS` 的部署仍受限（只是从精确目录放宽到根子树），不会突然暴露。

### 负面

- **完全放开 cwd（未设根时）**：前端可操作任意目录。**必须确保网络层（Tailscale / 认证）到位**，否则任意目录可被打开。README 的安全提醒需相应强化。
- **多一个 `browse_dir` 接口**（若做浏览选择器）：新增不绑定会话的目录浏览，需自带越界检查。
- **localStorage 跨设备不同步**：手机和电脑各自记忆「最近打开」，不互通。可接受（各自积累各自的常用项目）；若需同步，后续可改为服务端持久化。
