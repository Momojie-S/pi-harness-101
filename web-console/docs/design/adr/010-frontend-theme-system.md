# ADR-010: 前端主题系统与 Linear 视觉风格选型

## 状态

Accepted

## 背景

### 现状

web-console 前端**没有设计系统**，视觉靠 Tailwind 原子类硬编码在各组件 `className` 里：

- **配色扁平无层次**：全局 `bg-slate-950` 平铺，卡片 `bg-slate-900/60`、hover `bg-slate-800`，唯一的彩色是发送按钮 `blue-600`、工具名 `amber-400`。`tailwind.config.js` 的 `theme.extend` 是**空对象**——所有颜色散落在 8 个组件里，改主题要全局搜索替换。
- **只有暗色、且是写死的暗色**：无亮色主题、无主题切换能力。`App.tsx` 根容器 `bg-slate-950` 写死，`prefers-color-scheme` 完全没用。
- **移动端自适应缺陷**（逐条核实于源码）：
  - `index.html` 写了 `viewport-fit=cover`，但 CSS **完全没用** `env(safe-area-inset-*)`——刘海屏/手势条遮挡输入区与顶栏；
  - 触摸目标偏小：会话关闭 `✕`、目录项 `px-2 py-1.5`、按钮高度不足 44px；
  - 侧边栏抽屉 `sidebarOpen` 直接条件渲染，**无滑入过渡**；
  - 移动端顶栏只有汉堡按钮 + 一行 `text-xs` 小字，无标题/品牌。

### 问题

1. **"丑"的根因是缺少分层技法**：业界深色标杆（Linear / Vercel）用「**白色低透明度叠加**」（`rgba(255,255,255,0.04~0.14)`）做卡片分层与边框，产生"空气感"；我们用死灰（`slate-800/900`）平铺，自然显得闷、扁平。
2. **无主题切换**：只有写死的暗色，不满足"亮/暗双主题切换"的需求。
3. **移动端体验粗糙**：安全区、触摸目标、动画、顶栏均缺位。

### 关键事实：实测业界标杆 Linear 的设计系统

为避免凭空臆想配色，**实测了 Linear 官网**（`linear.app`，公开免登录，数据可信）的完整深色设计系统：

| 维度 | Linear 实测值 |
|---|---|
| 页面底色 | `#08090A`（近纯黑，带极微暖） |
| 卡片分层 | `#090A0B → #101112 → #161718 → #1A1B1F` 逐级抬升 |
| **分层神技** | hover/边框用 `rgba(255,255,255,0.04~0.14)`（白色低透明度叠加） |
| 强调色 | `#5E6AD2`（蓝紫 / 靛色） |
| 字体 | `Inter`（可变字体，SaaS 标配） |
| 圆角 | 4 / 6 / 8 / 12px（克制，最大 12px） |
| 主按钮 | 胶囊形（`border-radius: 9999px`） |

> ChatGPT、Claude.ai 需登录，未实测到真实聊天 UI；其风格特征以公开常识对照（见下「决策一」备选）。

## 面临的选择

本决策含三个相互独立的子决策。

### 决策一：视觉风格

| 方案 | 性格 | 代表 |
|------|------|------|
| **A. Linear 风** | 冷峻、精致、专业、近黑 | Linear、Vercel |
| B. ChatGPT 风 | 中性、亲和、圆润、偏暖灰 | ChatGPT |
| C. Claude 风 | 暖、文气、书卷气、陶土橙 | Claude.ai |

### 决策二：主题实现技术

| 方案 | 做法 |
|------|------|
| **A. CSS 变量语义令牌驱动** | 颜色定义为 CSS 变量，Tailwind 映射成语义 utility（`bg-surface` / `text-secondary` / `border-default`），组件用语义 class；切换主题只改变量值，组件代码不变 |
| B. Tailwind `dark:` 前缀 | 组件写 light 默认 + 每个 class 配 `dark:` 覆盖 |

### 决策三：字体

| 方案 | 做法 |
|------|------|
| **A. 引入 Inter 自托管 + 中文兜底** | 自托管 Inter（woff2 子集，仅拉丁/数字）；中文走系统字体（苹方/雅黑） |
| B. 纯系统字体栈 | 不引入，全用 `system-ui` 等 |

## 决策

**决策一选 A（Linear 风），决策二选 A（CSS 变量语义令牌），决策三选 A（Inter 自托管 + 中文兜底）。**

### 为什么是 Linear 风

1. **调性契合**：web-console 是「AI 编程助手的远程操控台」，开发者深夜在电脑/手机上用，近黑护眼、专业感强。
2. **根治"灰扑扑"**：「白色低透明度叠加」技法直接解决我们最大的视觉痛点，立竿见影。
3. **有实测数据可落地**：参数（底色/分层/强调/圆角）抄 Linear 即可，非空想配色。
4. **蓝紫强调 `#5E6AD2`** 比现状的纯蓝 `blue-600` 更高级，且语义平滑（强调色语义不变）。

### 为什么是 CSS 变量语义令牌（而非 Tailwind `dark:` 前缀）

1. **组件与主题彻底解耦**：组件只写 `bg-surface`，主题切换/换肤只改变量，组件代码零改动。`dark:` 前缀会让每个 utility 写两遍（`bg-white dark:bg-slate-900`），维护成本翻倍。
2. **天然支持任意多主题**：将来要加第三套（如高对比度、OLED 纯黑）只需加一组变量值。
3. **令牌集中管理**：颜色/圆角/间距集中在一处（`:root`），符合"设计系统单一事实来源"。
4. **代价可接受**：需在 `tailwind.config.js` 把变量映射成语义 utility（一次性），换来长期的低维护成本。

### 为什么引入 Inter

1. Inter 是现代 SaaS / 开发者工具的事实标准字体（Linear/Vercel/GitHub 均用），字形精致、可变字重。
2. 自托管 woff2 子集（仅拉丁/数字/常见符号）体积可控（~30KB/字重），中文天然走系统字体（苹方/雅黑），不引入中文字体（体积过大）。
3. 中英混排：英文/数字用 Inter 的精致字形，中文用系统字体的最佳渲染，兼顾体积与观感。

完整令牌定义（亮/暗双套色值、字体栈、圆角、阴影、移动端规范）见 [modules/design-system.md](../modules/design-system.md)。

## 备选方案

### 决策一（视觉风格）

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A. Linear 风（本决策）** | 专业、护眼、近黑质感、实测可落地、根治扁平 | 偏冷峻，少亲和力（对开发者工具是加分） |
| B. ChatGPT 风 | 大众化、亲和、认知成本低 | 偏暖灰、圆润，与"操控台"调性不贴；绿色强调辨识度一般 |
| C. Claude 风 | 文气、有书卷气、暖陶土独特 | 衬线标题偏阅读场景；陶土橙在开发者工具里略显花哨 |

### 决策二（主题技术）

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A. CSS 变量语义令牌（本决策）** | 组件/主题解耦、易换肤、令牌集中、支持多主题 | 需一次性建令牌层 + config 映射；多一层语义间接 |
| B. Tailwind `dark:` 前缀 | Tailwind 原生、零额外架构 | 每个 utility 写两遍、维护翻倍、换肤难 |

### 决策三（字体）

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A. Inter 自托管 + 中文兜底（本决策）** | 现代精致字形、业界标配、体积可控 | 产物 +~60KB（两字重 woff2）、需配 `@font-face` |
| B. 纯系统字体栈 | 零产物体积、零配置 | 中英混排观感取决于系统、不够精致统一 |

## 放弃了什么

- **Tailwind `dark:` 前缀的简单性**：换来组件与主题彻底解耦、可换肤。
- **ChatGPT / Claude 的调性**：用户授权选型，选定 Linear 风。
- **中文字体**：自托管中文字体体积过大（数 MB），不值得；中文走系统字体最佳渲染。
- **纯黑（#000）背景**：Linear 实测用 `#08090A`（近黑带极微暖），比纯黑更有质感、不易显脏。

## 后果

### 正面

- **根治"灰扑扑"**：「白色低透明度叠加」分层 + 近黑底色，视觉层次立现。
- **亮/暗双主题**：跟随系统（`prefers-color-scheme`）默认 + 手动切换 + `localStorage` 持久化，无 FOUC（内联脚本预设 `data-theme`）。
- **令牌集中**：后续微调/换肤只改变量，组件代码不动。
- **移动端完整优化**：safe-area 安全区、触摸目标 ≥40px、抽屉滑入动画、顶栏品牌，一次性补齐。
- **有实测标杆对照**：实现时按 Linear 实测参数校准，非主观判断。

### 负面

- **一次性改造量大**：8 个组件的硬编码 className 要逐个迁移为语义令牌（迁移映射表见 [design-system.md §10](../modules/design-system.md)）。**必须一次做完整**（方法论：完整 > 妥协），不留半迁移状态。
- **引入 Inter 字体**：产物 +~60KB（两字重 woff2 子集），可接受。
- **语义命名学习成本**：新人需理解 `bg-surface` / `text-secondary` 等语义令牌；通过 [design-system.md](../modules/design-system.md) 令牌表 + 组件对照缓解。
